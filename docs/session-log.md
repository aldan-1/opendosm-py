## 3. Key Decisions Made Today

### 3.1 Version Management
**Before:** `__version__` was hardcoded in both `__init__.py` and `pyproject.toml` — caused a drift bug (0.1.0 vs 0.1.1).
**After:** Single `_version.py` source. `__init__.py` and `http.py` import from it. `pyproject.toml` uses `dynamic = ["version"]` with `[tool.hatch.version] path = "src/opendosm/_version.py"`.

### 3.2 Dependency Management
**Before:** Dev deps were unpinned lower bounds. CI installed latest numpy (2.5.1) whose stubs use Python 3.12 `type` syntax — broke mypy with `python_version = "3.10"`.
**Decision:** Pin `numpy>=1.24,<2.5` in dev extras. Generate and commit `uv.lock` for reproducible environments. (Full uv migration in CI deferred to v0.2.0.)

### 3.3 CI Failure Resolution
**Problem:** mypy `ignore_errors=true` and `follow_imports="skip"` overrides both failed to suppress numpy stub syntax errors.
**Root cause:** Syntax errors in third-party stubs cannot be suppressed by mypy config — they abort the parse before overrides apply.
**Fix:** Pin numpy to `<2.5` (no `type` statement in stubs for 2.4.x).

### 3.4 Knowledge Base Strategy
**Decision:** Keep `knowledge base/` locally (gitignored — personal notes). Extract durable content into `docs/` (architecture, roadmap, api-coverage) for the public repo. Write this session log to `docs/` for transparency on the development process.

### 3.5 QA Fix: pytest Collection Bug
**Problem:** `tests/test_sdk_manual.py` had a helper function `def test(name, func):` that pytest auto-collected as a test item (naming collision with real tests).
**Fix:** Renamed to `run_test(name, func)`.
